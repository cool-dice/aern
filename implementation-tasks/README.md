# Задачи реализации стартового кода

Эта папка — единственный план реализации. Продуктовый код здесь не пишется. Каждый файл `NNN-*.md` — атомарная задача для одного имплементатора. Задача самодостаточна: формулы, имена, сигнатуры и решения противоречий скопированы внутрь, чтобы не перечитывать весь GDD.

## Статусы

| Статус | Значение |
|---|---|
| `pending` | Не начата. Все задачи стартуют в этом статусе. |
| `in_progress` | Исполнитель взял задачу и ещё не сдал её. |
| `done` | Код и юнит-тесты задачи есть в ветке, тесты задачи зелёные. |

Менять статус в заголовке файла имеет право только исполнитель этой задачи, в том же коммите, что и код. Не переписывать чужие задачи.

## Правила зависимостей

- Поле `depends_on` — список id (`001`, `004`). Начинать задачу можно только когда все зависимости в статусе `done`.
- Внутри одной волны задачи **не делят файлы**. Их можно отдавать параллельным субагентам.
- Задачи из разных волн, если указано «строго последовательно», нельзя распараллеливать: они пишут одни и те же файлы или публичный barrel.
- Один коммит — одна задача (или явно названный в задаче тесный кластер). После коммита дерево должно собираться и прогонять уже написанные юнит-тесты.
- Юнит-тесты только. Не добавлять Playwright, браузерные тесты, k6, GitHub Actions, Kubernetes, Grafana, Loki, ClickHouse, Steam.
- Тесты детерминированы и не требуют живого сервера, PostgreSQL, Redis или сети. Доступ к данным в тестах — in-memory double, описанный в задаче.
- Идентификаторы кода — английские, как в задачах. Проза задач — русская, язык документов.

## Как запускать тесты (после того, как код появится)

Команды зафиксированы задачей `001` и корневым `README.md` задачи `055`:

```bash
pnpm install
pnpm test
pnpm --filter @rift/domain test
pnpm --filter @rift/server test
pnpm --filter @rift/client test
pnpm --filter @rift/protocol test
pnpm --filter @rift/content test
cargo test --manifest-path apps/sidecar/Cargo.toml
```

`pnpm test` гоняет Vitest через Turborepo и не поднимает Docker. `docker compose up` нужен только для ручного запуска сервера с PostgreSQL и Redis, не для тестов.

## Что сознательно не входит в стартовый код

Смотри `00-overview.md`, раздел «Граница стартового кода». Кратко: нет E2E, нет пайплайнов деплоя, нет Kubernetes, Grafana, Loki, ClickHouse, монетизации, Steam. Доменные правила гильдий, аукциона, почты и титулов реализованы и покрыты тестами, но мутирующие серверные операции прототипа возвращают `feature_stub`, как требует артефакт 30.
