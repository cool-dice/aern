# Модели экранов интерфейса

- id: `049`
- title: Модели экранов интерфейса
- status: `pending`
- depends_on: `001`, `029`

## Цель

Описать чистые view-model экранов прототипа, чтобы React потом их только рисовал. Без jsdom и без браузера.

## Контекст

Артефакты 27 и 30. Экраны: главное меню, создание персонажа, сцена (данные HUD), инвентарь, экипировка (слоты head, torso, main_hand, core видны всегда; остальные слоты помечены `advanced` и в прототипе скрыты флагом), крафт (только 8 рецептов), квесты, карта с туманом, чат, торговля прямым обменом, взлом 4×4, уведомления 6 типов, настройки масштаба и colorblind.

Туман войны: известные узлы из массива `visited`. Неизвестный узел не отдаётся в список карты, только ребро к нему как «неизвестно», если сосед посещён.

Уведомления: system, quest, combat, economy, social, world. Длительности 5, 5, 2, 5, 5, 10 секунд. `expire(list, now)` снимает просроченные.

Создание персонажа: расы только human для игрока. Очки сумма 20, превью статов через домен `createCharacter` если валидно, иначе текст ошибки кода.

Цветовые режимы: `none`, `protanopia`, `deuteranopia`, `tritanopia`. Это поле настроек, не шейдер. Палитры — словари `enemy`, `ally`, `neutral`, `keeper` в шести hex. Для none: враг `#c0392b`, союзник `#27ae60`, нейтрал `#7f8c8d`, хранитель `#f1c40f`. Для трёх режимов задать различимые hex, не равные друг другу внутри палитры. Тест проверяет уникальность четырёх цветов в каждом режиме.

Масштаб UI: 1, 1.25, 1.5. Иной → ошибка.

Разрешения в настройках не режем логикой: записать константы 1280×720 и 3840×2160 как поддерживаемые границы, без проверки монитора.

## Решение противоречий

Экипировка E в меню не является отдельным экраном-хоткеем. View-model инвентаря содержит вкладку equipment.

Чат на 6 каналов: пять рабочих моделей плюс mail и guild помечены `stub: true` и не имеют поля ввода.

## Файлы

- `apps/client/src/ui/models.ts`
- `apps/client/src/ui/models.test.ts`
- `apps/client/src/ui/screens.tsx` — тонкие компоненты, которые получают model и возвращают React-элементы. Их не тестировать библиотекой. Допустим рендер без теста. Если JSX мешает vitest-node, компоненты в `screens.tsx` не импортировать из теста.

## Интерфейсы

Функции: `menuModel()`, `creationPreview(input)`, `inventoryModel(items, prototypeSlots: boolean)`, `craftModel(recipes, prototypeOnly: boolean)`, `mapModel(nodes, visited)`, `notificationPush`, `palette(mode)`, `chatModel(channels)`.

## Алгоритм

- prototypeOnly оставляет 8 id рецептов из задачи 029.
- inventory при prototypeSlots скрывает hands, legs, off_hand, импланты головы и ног. Показывает implant_torso и implant_hands.
- карта: узел вне visited отсутствует в `visible`.

## Тесты

- крафт-модель прототипа длиной 8 и содержит `rusty_sword`, не содержит уникальный клинок, если тот есть во входном списке.
- туман прячет непосещённый данж.
- уведомление combat живёт 2000 мс, world 10000. expire на границе снимает.
- палитры из 4 уникальных цветов.
- масштаб 2 → ошибка, 1.25 ок.
- чат mail stub true.
- превью человека с 20 очками возвращает body 16 для распределения 10/5/5/0/0/0.

## Definition of done

Тест не импортирует `screens.tsx` и не использует jsdom.
