## Cycle-9 wiring that still holds

2. **Attacks are blocked in the one-node radius around a city.** `inCitySafeRadius` is true on a graph neighbor of a city. `combatZone` returns a safe zone there before war and pvp flags. `applyAttack` calls `combatZone`. Verified: `inCitySafeRadius`, `combatZone`, `applyAttack`.

3. **A dropped node chest stays for the next planter.** `settleNodeDrop` leaves the chest and `seized: null` when the guild id becomes null. A later plant with `chest > 0` seizes it. `advanceResourceNode` is the caller. `tickOnce` and `skipMs` call `tickResourceNodes` and `applyNodeSeizure`. Verified: `settleNodeDrop`, `advanceResourceNode`, `tickResourceNodes`, `applyNodeSeizure`.

4. **Vassal release waits out the notice.** `tickOnce` and `skipMs` call `tickVassalReleases` → `releaseVassal`. `breakStoredPact` uses `releaseVassal` for a vassal and `breakAlliance` for an alliance. Verified: `tickVassalReleases`, `releaseVassal`, `breakStoredPact`, `breakAlliance`.

5. **A suzerain who never defends pays the pact-breach penalty.** `tickOnce` and `skipMs` call `noteSuzerainPresence` and `penalizeAbsentSuzerains` → `failSuzerainDefense` → `breachNonAggression` (`NAP_BREACH_GOLD` 50_000, `NAP_FLAG_MS` 7 days). Verified: `noteSuzerainPresence`, `penalizeAbsentSuzerains`, `failSuzerainDefense`, `breachNonAggression`.

6. **An escort completes only after the mercenary walks the route.** `postMercenary` stores `destinationId`. `tickContracts` appends the walked node and calls `contractDuty` → `escortArrived`. `tickContract` pays only when `duty` is true. Verified: `postMercenary`, `escortArrived`, `contractDuty`, `tickContracts`, `tickContract`.

7. **Section 11 collusion freezes rewards.** `reviewDeclaredWar` and `reviewNewSettlements` call `section11For` → `reviewSection11`. `freezeRewards` adds the attacker to `frozenGuilds`. `creditGuildBank` returns immediately for a frozen guild. Verified: `reviewSection11`, `section11For`, `reviewDeclaredWar`, `reviewNewSettlements`, `creditGuildBank`.

8. **A new war can settle on a city that already has a hold.** `tickCaptures` simulates the latest started war for a city. A declare clears `settledReviewed` for that city. Verified: `tickCaptures`, `reviewDeclaredWar`.

9. **A live auction buyout records 5% in `taxLedger` and credits the guild bank.** `auctionBid` calls `sellerProceeds`, `creditTax` (unless `rewardsFrozen`), and `recordAuctionTax`. Verified: `auctionBid`, `sellerProceeds`, `creditTax`, `recordAuctionTax`.

10. **Muster camps spawn from `tickOnce`.** `tickOnce` calls `openWarFronts()`, which calls `spawnMusterCamps` before the world copy. `skipMs` does not call `openWarFronts`. `main.ts` uses `void built.tickOnce()`. Verified: `openWarFronts`, `spawnMusterCamps`, `tickOnce`, `skipMs`.

## Wired this cycle

1. **Guild creation voting and dissolution are live routes the session posts.** `POST /guild/vote` is `guild_vote` → `castLeaderBallot` → `finishLeaderPoll` → `castLeaderVote`. `guildCreate` calls `openLeaderPoll` after a successful create. A tie stores `tieAtMs`. `tickOnce` calls `resolveLeaderPolls`, which calls `finishLeaderPoll` again only when `now >= tieAtMs + REVOTE_MS` (24 hours) and sets `revote` so the second tie uses `voteRng`. `finishLeaderPoll` also calls `voteQuorum` (`ballots * 2 >= eligible`) before it saves a leader and calls `seatFounders`. `POST /guild/dissolve` is `guild_dissolve` → `dissolveGuild` → `canDissolve`, then `dissolveShares`. Shares credit character gold. The remainder is `dissolutionVoid`. `POST /guild/deposit` is `guild_deposit` → `depositGuild`, which records the gold that entered the bank in `contributions`. `App.tsx` calls `castLeaderVote` and `dissolveGuild`. Verified: `openLeaderPoll`, `castLeaderBallot`, `finishLeaderPoll`, `castLeaderVote`, `voteQuorum`, `resolveLeaderPolls`, `canDissolve`, `dissolveShares`, `dissolveGuild`, `depositGuild`, `seatFounders`.

2. **One vote per character. An AI ballot is stored only while that bot is online.** `castLeaderBallot` returns `stuffed` when that `voterId` already has a ballot, before the new ballot is stored. A character with `controller === 'bot'` returns `offline`, and the ballot is not stored, unless an entity with that id is `phase === 'online'` and `carrierOffline` is not true. This function does not call `reviewSection11`. Bot rows inside `section11For` still feed the abuse note. They are not this route. Verified: `castLeaderBallot`, `section11For`, `reviewSection11`.

3. **A multibox carrier is refused before the war is saved or charged.** `guildWar` calls `carrierBlocked` before `declareNeutralCity` and before `ports.guild.declareWar`. `declareNeutralCity` calls `carrierBlocked` again before `saveGuild` and `saveWar`. `carrierBlocked` calls `reviewSection11` with `next: null` and the guild's bot carriers. Verified: `carrierBlocked`, `guildCarriers`, `reviewSection11`, `guildWar`, `declareNeutralCity`.

4. **A reward freeze ends on a later tick, and a withdrawal during that freeze is held.** Section 11 says rewards stay frozen until a review ("до проверки") and does not name a duration. `section11For` records `rewardFreezes` at the clock time of the review that opened the case. `tickOnce` calls `inspectRewardFreezes` → `rewardFreezeEnds` (`nowMs > frozenAtMs`). The opening timestamp does not clear the set. The next `tickOnce` deletes that guild from `frozenGuilds` and calls `releaseHeldWithdrawals`. `skipMs` does not call `inspectRewardFreezes`, so a clock skip that only opens the case still reports the guild frozen. `guildWithdraw`, when `rewardsFrozen` is true, calls `holdWithdrawal` and does not call `guild.service.withdraw`. `holdWithdrawal` calls domain `withdraw` first, so rank limits and the large-withdrawal confirm still fail the request. A passing amount is stored and `logWithdrawal` runs. The bank is not debited. `releaseHeldWithdrawals` is what later calls `guild.service.withdraw`. Verified: `rewardFreezeEnds`, `inspectRewardFreezes`, `holdWithdrawal`, `withdraw`, `logWithdrawal`, `releaseHeldWithdrawals`, `guildWithdraw`, `rewardsFrozen`.

## Still open

- The GDD is not complete.
- Section 3.3's internal ballot is not a second route. There is no 24-hour window on a non-leader vote, no leader deciding vote on a tie, and no senior-council fallback when the leader has been absent for 24 hours. The creation poll resolves as soon as `castLeaderVote` elects someone and `voteQuorum` passes. The 24-hour wait is only the revote after a tie (`REVOTE_MS`).
- `guildCreate` calls `seatFounders` before `openLeaderPoll`, so non-leaders are already novices while the creation poll is open. `finishLeaderPoll` does not pass `ranks` into `castLeaderVote`. Novices are therefore not rejected on this route. Passing ranks would block the creation vote, because step 8 of section 2.2 (starting ranks) is applied before the ballots exist.
- Section 2.5 is not implemented. Nothing transfers leadership after 14 days of leader absence, and nothing dissolves a guild that has no council and no officers.
- Dissolution splits gold that `depositGuild` recorded. Resource and item contributions are not a ledger. `dissolveShares` is still the gold formula. An empty contribution table sends the whole bank to `void`.
- One carrier, one bot is enforced when a war is declared (`carrierBlocked`). It is not enforced when the guild is created or when the second bot joins. Two bots of one account can sit in the guild until a war post.
- `reviewSection11` still classifies bot ballots (`stuffed` / `offline`) for the abuse note. That classification does not accept or store a vote.
- `frozenGuilds` clears on the next `tickOnce` after the review that opened the case (`nowMs > frozenAtMs`). The artifact does not name a longer investigation. There is no separate reviewer queue. `skipMs` does not clear the freeze. `releaseHeldWithdrawals` debits the guild bank through `guild.service.withdraw` and does not credit the character wallet. That matches the existing withdraw path.
- Section 8.3's "захватчик" is the guild that already owns the node. `strikeNodeFlag` returns `owner` for any other guild. A hostile guild cannot take the flag down and pocket the chest through this route.
- Section 12's war-duration row (1–1.5 real hours) is a design target. Section 5's phases are muster 30 minutes, assault 60, hold up to 10, and finish 5, which can run longer than 90 minutes. `measureSection12` reports `onTarget: false` outside 60–90 minutes. The phases were not rewritten, and the targets are not gates. The sentence that names no action was not turned into a formula.
- `skipMs` still does not call `openWarFronts`, `resolveLeaderPolls`, `inspectRewardFreezes`, `refreshPortalLifts`, or `sampleBalance`. Production is `tickOnce`.
- Guild creation still does not store an emblem or a description. Name moderation beyond `OFFICE_COOLDOWN_MS` is not a new check. The bank's 500 item slots and the per-rank item and resource withdrawal caps are not on `withdraw`. An AI still is not blocked from holding more than one leadership post.
- No Steam listing and no trained GPU weight file. Those were not required.
