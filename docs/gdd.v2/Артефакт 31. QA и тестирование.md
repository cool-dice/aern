# Артефакт 31. QA и тестирование

## 1. Общие принципы

- QA — непрерывный процесс, а не этап. Тесты пишутся вместе с кодом.
- Все изменения проходят через CI/CD. Без прохождения тестов — нет мержа.
- Приоритет — **играбельность ядра**, затем контент, затем полировка.
- Тестирование ведётся на трёх уровнях: юнит, интеграция, система.
- AI-боты тестируются через симулятор, а не вручную.
- Нагрузочные тесты проводятся перед каждым релизом.
- Все баги классифицируются по приоритету и серьёзности.
- Тестирование не заменяет плейтесты. Живые игроки находят то, что не находят автотесты.

| Модуль | Что тестируется |
|---|---|
| **Perception** | Вектор наблюдения |

- Каждая функция имеет минимум один тест.
- Каждый багфикс сопровождается тестом.
- Покрытие не ниже 70% по каждой ветке.
- Тесты быстрые (< 1 сек на тест).

## 10. Классификация багов

### 10.1. По серьёзности

| Уровень | Описание | Пример |
|---|---|---|
| **S1 — Критический** | Игра не работает | Краш сервера |
| **S2 — Высокий** | Ломает геймплей | Невозможно завершить бой |
| **S3 — Средний** | Мешает, но играбель | Неверный урон |
| **S4 — Низкий** | Косметика | Опечатка в тексте |

### 10.2. По приоритету

| Уровень | Описание | Срок |
|---|---|---|
| **P1 — Срочный** | Блокирует релиз | 24 часа |
| **P2 — Высокий** | Ломает геймплей | 3 дня |
| **P3 — Средний** | Мешает | 1 неделя |
| **P4 — Низкий** | Косметика | Следующий релиз |

### 10.3. Процесс

1. Баг найден → создаётся issue.
2. Классифицируется по S и P.
3. Назначается ответственный.
4. Исправляется.
5. Пишется тест.
6. Тест проходит.
7. Баг закрывается.

## 11. Автоматизация

### 11.1. CI/CD

- GitHub Actions.
- При push: юнит-тесты.
- При PR: юнит + интеграционные.
- Перед релизом: все тесты.

### 11.2. Пайплайн

```
Push → Линт → Юнит → Интеграция → Сборка → E2E → Деплой на staging → Нагрузочные → Деплой на prod
```

## 15. Процесс релиза

### 15.1. Перед релизом

1. Все тесты проходят.
2. Нет багов S1 и S2.
3. Нагрузочные тесты пройдены.
4. Плейтесты пройдены.
5. Метрики в норме.
6. Документация обновлена.

### 15.2. Релиз

1. Сборка.
2. Деплой на staging.
3. Финальные тесты.
4. Деплой на prod.
5. Мониторинг 24 часа.
6. Откат при критических ошибках.

### 15.3. После релиза

1. Сбор обратной связи.
2. Мониторинг метрик.
3. Хотфиксы при необходимости.
4. Планирование следующего релиза.
