# Артефакт 24. Архитектурные решения

## 1. Общие принципы

- Архитектура — **модульный монолит** на сервере и **тонкий клиент** на стороне игрока.
- Единый источник истины — сервер. Клиент — только ввод, рендер и локальный инференс AI.
- Игровая логика не зависит от транспорта. Сетевой слой изолирован.
- AI-инференс вынесен на клиент. Сервер не тратит ресурсы на нейросети.
- Все длительности — в реальном времени.
- Разработка ведётся одним человеком с ИИ-агентами. Стек выбран под эту модель.
- Система проектируется под **1000–2000 одновременных игроков на шард**.

## 2. Выбор технологий

### 2.1. Клиент

| Компонент | Технология | Обоснование |
|---|---|---|
| Обёртка | **Tauri (Rust)** | Малый размер, нативный доступ к GPU, кроссплатформенность |
| UI | **React + TypeScript** | Зрелость, скорость разработки, поддержка ИИ-агентами |
| Рендер | **PixiJS** | Спрайтовый псевдо-3D, лёгкий, работает в WebView |
| Сеть | **WebSocket** | Реалтайм, зрелость, поддержка в браузере |
| AI-инференс | **Rust-сайдкар (llama.cpp / ONNX Runtime)** | Изоляция, производительность, доступ к GPU |
| Состояние | **Zustand** | Простой стейт-менеджмент для React |

### 2.2. Сервер

| Компонент | Технология | Обоснование |
|---|---|---|
| Runtime | **Node.js 20+** | Асинхронность, скорость разработки |
| HTTP | **Fastify** | Быстрый, модульный, поддержка WebSocket |
| Реалтайм | **WebSocket (ws)** | Авторитарная синхронизация |
| Кэш | **Redis 7+** | Реалтайм-состояние, сессии, очередь |
| БД | **PostgreSQL 16+** | Персистентность, транзакции |
| Вектор | **pgvector** | Память AI-ботов |
| Очередь | **BullMQ (Redis)** | Фоновые задачи: обучение, аналитика |

### 2.3. Инфраструктура

|---|---|---|
| Контейнеризация | **Docker** | Единообразие среды |

| Прокси | **Nginx / Caddy** | TLS-терминация, rate limiting |
| Мониторинг | **Prometheus + Grafana** | Метрики, алерты |
| Логи | **Loki + Grafana** | Централизованные логи |
| Трейсинг | **OpenTelemetry** | Сквозная трассировка |
| CI/CD | **GitHub Actions** | Автосборка, тесты, деплой |

### 2.4. Разработка

| Компонент | Технология |

## 3. Клиентская архитектура

### 3.1. Слои

```
Tauri (Rust) — обёртка, GPU, файлы
    ↓
Rust-сайдкар — AI-инференс
    ↓ IPC
React (TS) — UI, стейт, сеть
    ↓
PixiJS — рендер
```

### 3.2. Модули клиента

| Модуль | Ответственность |
|---|---|
| **Core** | Запуск, жизненный цикл, конфиг |
| **Network** | WebSocket, реконнект, очередь команд |
| **State** | Zustand-стор, синхронизация с сервером |
| **Render** | PixiJS-сцена, спрайты, анимации |
| **UI** | React-компоненты: инвентарь, чат, карта |
| **Input** | Клавиатура, мышь, тач |
| **AI** | Мост к Rust-сайдкару, отправка команд бота |
| **Assets** | Загрузка, кэш, атласы |
| **Audio** | Адаптивная музыка, эффекты |

### 3.3. Предсказание

- Локальное предсказание **только движения**.
- Атаки, способности, лут — только с сервера.
- При расхождении — откат к серверному состоянию.
- Буфер предсказаний: 500 мс.

### 3.4. Rust-сайдкар

| Параметр | Значение |
|---|---|
| Процесс | Отдельный, запускается Tauri |
| Связь | IPC (stdin/stdout, JSON) |
| Policy | 10 млн параметров, 8 бит |
| LLM | 1–3 млрд параметров, 4 бита |
| Библиотеки | llama.cpp, ONNX Runtime |
| GPU | Vulkan, DirectML, CUDA |
| Fallback | Ошибка запуска → клиент не стартует |

## 4. Серверная архитектура

### 4.1. Модульный монолит

```
Fastify (HTTP + WebSocket)
    ↓
Modules (игровая логика)
    ↓
Repositories (доступ к данным)
    ↓
PostgreSQL + Redis
```

### 4.2. Модули сервера

| Модуль | Ответственность |
|---|---|
| **Auth** | Регистрация, вход, токены |
| **Character** | Персонажи, статы, инвентарь |
| **World** | Узлы, рёбра, регионы |
| **Combat** | Бой, урон, статусы |
| **Dungeon** | Генерация, инстансы |
| **Craft** | Рецепты, крафт, разбор |
| **Economy** | Аукцион, торговля, налоги |
| **Quest** | Квесты, цепочки, прогресс |
| **Guild** | Гильдии, войны, налоги |
| **Social** | Чат, титулы, контракты |
| **Event** | Мировые события, сезоны |
| **AI** | Валидация действий ботов |
| **Wiki** | Библиотека, знания |
| **Admin** | Модерация, баны |

### 4.3. Изоляция

- Каждый модуль имеет чёткий публичный интерфейс.
- Модули общаются через шину событий (EventEmitter).
- Прямые вызовы между модулями запрещены.
- Это упрощает тестирование и замену модулей.

### 4.4. Симуляция

- **Tick rate:** 10 в секунду.
- Один тик: движение, бой, кулдауны, статусы, события.
- Состояние рассылается после тика.
- Симуляция детерминирована по сиду.

## 5. Хранение данных

### 5.1. PostgreSQL

| Группа | Таблицы |
|---|---|
| **Персонажи** | characters, stats, inventory, equipment |
| **Мир** | nodes, edges, regions, instances |
| **Бой** | combats, damage_log, statuses |
| **Квесты** | quests, quest_progress |
| **Экономика** | auctions, trades, taxes |
| **Гильдии** | guilds, members, wars, taxes |
| **Социальное** | chats, mail, titles, contracts |
| **AI** | bots, memories, knowledge_graph |
| **Wiki** | articles, versions, votes |
| **События** | events, seasons, weather |

### 5.2. Redis

| Ключ | Назначение | TTL |
|---|---|---|
| `session:{id}` | Сессия игрока | 24 ч |
| `state:{entity}` | Реалтайм-состояние | 1 ч |
| `instance:{id}` | Инстанс данжа | 10 мин после выхода |
| `queue:{type}` | Очередь задач | — |
| `lock:{resource}` | Блокировки | 30 с |
| `cache:{key}` | Кэш | 5 мин |

### 5.3. pgvector

- Векторная память AI-ботов.
- Размерность: 768.
- Индекс: IVFFlat.
- Поиск: косинусная близость.

### 5.4. Файловое хранилище

- Адаптеры AI (LoRA) — S3-совместимое.
- Логи — Loki.
- Ассеты — CDN.

## 6. Сетевой слой

### 6.1. Протокол

- **WebSocket (TLS 1.3)** — основной канал.
- **HTTP** — статика, аутентификация.
- **JSON** — формат сообщений.

### 6.2. Каналы

| Канал | Приоритет | Частота |
|---|---|---|
| State | Высокий | 10/сек |
| Command | Высокий | По событию |
| Chat | Средний | По событию |
| Market | Низкий | По событию |
| Social | Низкий | По событию |
| System | Высокий | По событию |

### 6.3. Синхронизация

- Клиентское предсказание — только движение.
- Серверная валидация — все действия.
- Лаг-компенсация — 500 мс.
- Интерполяция — 100 мс.

## 7. AI-инференс

### 7.1. Расположение

- Policy и LLM — на клиенте игрока.
- Rust-сайдкар — изолированный процесс.
- Сервер — только валидация.

### 7.2. Требования

| Параметр | Минимум |
|---|---|
| GPU | 4 ГБ VRAM, Vulkan/DirectML |
| CPU | 4 ядра |
| RAM | 8 ГБ |
| ОС | Windows 10, Linux |

### 7.3. Обязательность

- Запуск AI-бота — системное требование.
- Без него клиент не стартует.
- Это часть минимальных требований проекта.

### 7.4. Мотивация

- Отсутствует. Это контракт, не награда.

## 8. Безопасность

### 8.1. Аутентификация

- Токен при входе.
- Сессионный ключ.
- HMAC-SHA256 для команд.

### 8.2. Античит

- Серверная валидация всех действий.
- Проверка ОД, дистанции, кулдаунов, ресурсов.
- Логирование аномалий.
- Бан при повторных нарушениях.

### 8.3. Защита

- TLS 1.3.
- Rate limiting.
- Cloudflare.
- Изоляция сайдкара.

### 8.4. Модерация

- Серверная, не гильдейская.
- Репорты, мьюты, баны.
- Логирование чата.

## 9. Масштабирование

### 9.1. Шардирование

- Один сервер — один шард.
- 1000–2000 игроков на шард.
- Шарды по регионам.
- Миграция персонажа между шардами.

### 9.2. Горизонтальное

- Redis Cluster — при росте.
- PostgreSQL — репликация, партиционирование.
- Load balancer — перед шардами.

### 9.3. Вертикальное

- Node.js кластер с воркерами.
- Redis — выделенный сервер.
- PostgreSQL — выделенный сервер.

## 12. Модульность

### 12.1. Правила

- Модуль = папка с публичным API.
- Импорт из другого модуля — только через API.
- Прямой доступ к БД другого модуля запрещён.
- Общение — через шину событий.

### 12.2. Пример структуры

```
/server
  /modules
    /character
      index.ts        — публичный API
      service.ts      — логика
      repository.ts   — доступ к БД
      types.ts        — типы
    /combat
    /economy
  /shared
    /db
    /redis
    /events
  /infra
    /http
    /ws
    /auth
```

### 12.3. Преимущества

- Тестируемость.
- Заменяемость.
- Параллельная разработка.
- ИИ-агенты работают с модулями изолированно.
