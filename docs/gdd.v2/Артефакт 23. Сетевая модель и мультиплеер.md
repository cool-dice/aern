# Артефакт 23. Сетевая модель и мультиплеер

## 1. Общие принципы

- Сетевая модель — **авторитарный клиент-сервер**.
- Сервер — единственный источник истины. Все действия валидируются.
- Клиент отправляет команды. Сервер применяет их и рассылает состояние.
- Клиент никогда не считается доверенным. Любое расхождение трактуется в пользу сервера.
- AI-боты работают по тому же протоколу, что и игроки. Сервер не различает их.
- Все длительности — в реальном времени.
- Сетевой код изолирован: игровая логика не зависит от транспорта.

---

## 2. Топология

### 2.1. Архитектура

```
Клиент (Tauri + React + PixiJS)
        ↓ WebSocket (TLS)
Сервер (Node.js + Fastify)
        ↓
Redis (реалтайм) + PostgreSQL (персистентность)
        ↓
Rust-сайдкар (AI) — на клиенте
```

### 2.2. Компоненты

| Компонент | Роль | Ответственность |
|---|---|---|
| **Клиент** | Тонкий | Ввод, рендер, предсказание, инференс AI |
| **Сервер** | Авторитарный | Валидация, состояние, симуляция, рассылка |
| **Redis** | Кэш | Реалтайм-состояние, сессии, очередь |
| **PostgreSQL** | Хранилище | Персистентность, память ботов, вики |
| **Rust-сайдкар** | Локальный | Инференс policy и LLM для AI-бота |

### 2.3. Шардирование

- Один сервер — один шард.
- Целевой онлайн: **1000–2000** одновременно.
- Шардирование по регионам — при росте.
- Перенос персонажа между шардами — только через миграцию.

---

## 3. Протокол

### 3.1. Транспорт

- **WebSocket (TLS 1.3)** — основной канал.
- **HTTP** — только для статики, аутентификации и загрузки ассетов.
- **Формат сообщений:** JSON.
- **Бинарный формат:** не используется в v1.

### 3.2. Каналы

| Канал | Назначение | Приоритет |
|---|---|---|
| **State** | Обновление состояния мира | Высокий |
| **Command** | Команды клиента | Высокий |
| **Chat** | Чат, почта | Средний |
| **Market** | Аукцион, торговля | Низкий |
| **Social** | Гильдии, титулы, контракты | Низкий |
| **System** | Уведомления, ошибки | Высокий |

### 3.3. Аутентификация

1. Клиент отправляет токен при подключении.
2. Сервер проверяет токен.
3. Сервер выдаёт сессионный ключ.
4. Все команды подписываются сессионным ключом.
5. Сервер проверяет подпись каждой команды.

### 3.4. Шифрование

- TLS 1.3 для WebSocket.
- Подпись команд HMAC-SHA256.
- Токены хранятся в защищённом хранилище клиента.

## 4. Частота и тики

### 4.1. Серверный тик

- **Tick rate:** 10 тиков в секунду (100 мс).
- Один тик = один шаг симуляции.
- Симуляция: движение, бой, кулдауны, статусы, события.
- Состояние рассылается после каждого тика.

### 4.2. Клиентский рендер

- **Render rate:** 60 FPS.
- **Интерполяция:** между тиками сервера.
- **Экстраполяция:** до 200 мс при потере пакетов.

### 4.3. Обновление состояния

| Категория | Частота |
|---|---|
| Позиции существ | 10 раз в секунду |
| HP, ОД, статусы | 10 раз в секунду |
| Инвентарь, экипировка | По изменению |
| Квесты, гильдия | По изменению |
| Аукцион, вики | По запросу |
| События, погода | По изменению |

---

## 5. Синхронизация

### 5.1. Клиентское предсказание

- Клиент предсказывает **движение** локально.
- Предсказание откатывается при расхождении с сервером.
- Атаки, способности, предметы — **не предсказываются**.
- Урон, лут, статусы — **только с сервера**.

### 5.2. Серверная валидация

Сервер проверяет каждую команду:

| Проверка | Описание |
|---|---|
| **ОД** | Достаточно ли очков действия |
| **Дистанция** | В пределах лимита |
| **Линия видимости** | Нет препятствий |
| **Кулдаун** | Умение готово |
| **Ресурсы** | Предметы, патроны, энергия |
| **Цель** | Существует, враждебна, доступна |
| **Зона** | Действие разрешено (PvP, сейф-зона) |
| **Статусы** | Нет оглушения, обездвиживания |
| **Вес** | Нет перегруза |
| **НН** | Не превышен лимит |

При провале — команда отклоняется, клиент получает ошибку.

### 5.3. Лаг-компенсация

- Сервер хранит состояние за последние **500 мс**.
- При выстреле сервер откатывает состояние на момент выстрела.
- Проверяет попадание.
- Применяет результат к текущему состоянию.
- Это компенсирует пинг до **250 мс**.

### 5.4. Интерполяция

- Клиент получает состояние каждые 100 мс.
- Между тиками интерполирует позиции существ.
- Задержка интерполяции: **100 мс**.
- Это сглаживает движение.

## 6. Конфликты действий

### 6.1. Одновременные действия

- Приоритет по **Реакции**.
- При равенстве Реакции — случайный выбор.
- Сервер разрешает конфликт: кто первым отправил команду, тот и получает приоритет.
- При равенстве timestamp — по инициативе.

### 6.2. Атака и уклонение

1. Атакующий отправляет команду атаки.
2. Сервер проверяет ОД, дистанцию, линию видимости.
3. Сервер сравнивает Точность атакующего и Уклонение цели.
4. Если Точность > Уклонение — попадание.
5. Если Уклонение ≥ Точности — цель тратит 1 ОД и уклоняется.
6. Результат рассылается всем в зоне.

### 6.3. Бой в группе

- Friendly fire выключен по умолчанию.
- Лечение союзника — через команду.
- Подъём союзника — через «Споровый шокер».

---

## 7. Смерть и выход

### 7.1. Смерть

- При 0 HP персонаж переходит в «тяжёлый».
- Лут падает на труп.
- Труп существует 2 реальных часа.
- Возрождение у привязки.
- Сохраняется: прокачка, хранилище, знания, титулы.

### 7.2. Выход из игры

- При выходе персонаж остаётся в мире **10 минут** (грэйс).
- В это время он уязвим.
- Через 10 минут — исчезает, появляется в привязке.
- Если игрок вышел в бою — грэйс не применяется, персонаж уязвим сразу.

### 7.3. Реконнект

- Клиент автоматически переподключается.
- Сервер восстанавливает сессию.
- Состояние синхронизируется.
- Пропущенные события воспроизводятся из Redis.

---

## 8. AI-боты

### 8.1. Протокол

- Бот использует тот же WebSocket-канал, что и игрок.
- Команды бота подписаны сессионным ключом носителя.
- Сервер валидирует действия бота как клиента.
- Сервер не различает игрока и бота.

### 8.2. Инференс

- Policy и LLM работают на GPU носителя.
- Rust-сайдкар общается с клиентом через IPC.
- Клиент отправляет команды бота на сервер.

### 8.3. Офлайн

- При офлайне носителя бот исчезает из мира.
- Состояние сохраняется.
- При возвращении бот появляется в привязке.

---

## 9. Безопасность

### 9.1. Античит

- Серверная валидация всех действий.
- Проверка ОД, дистанции, кулдаунов, ресурсов.
- Невозможные действия отклоняются.
- Подозрительная активность логируется.
- При повторных нарушениях — временный бан.

### 9.2. Защита от DDoS

- Rate limiting на уровне сервера.
- Cloudflare или аналог.
- Ограничение соединений с одного IP.

### 9.3. Защита от читов

- Клиент не может влиять на урон, лут, позиции.
- Все расчёты на сервере.
- Клиент только отправляет команды.

### 9.4. Логирование

- Все команды логируются.
- Все ошибки логируются.
- Логи хранятся 30 дней.

---

## 10. Масштабирование

### 10.1. Шардирование

- Один сервер — один шард.
- Шарды по регионам.
- Переход между шардами — через миграцию.
- Миграция: персонаж копируется, блокируется на время.

### 10.2. Балансировка

- Балансировщик распределяет игроков по шардам.
- При перегрузке — новые игроки на свободный шард.
- При падении шарда — игроки переподключаются.

### 10.3. Redis

- Реалтайм-состояние.
- Сессии.
- Очередь задач.
- Кэш инстансов данжей.

### 10.4. PostgreSQL

- Персистентность.
- Память ботов.
- Вики.
- Аукцион.

---

## 11. Обработка ошибок

### 11.1. Потеря пакетов

- WebSocket использует TCP.
- TCP гарантирует доставку.
- При потере — повторная отправка.

### 11.2. Задержки

- При пинге > 250 мс — клиент предупреждает.
- При пинге > 500 мс — клиент отключается.
- При реконнекте — восстановление состояния.

### 11.3. Дублирование команд

- Каждая команда имеет timestamp.
- Дубликаты отсекаются.
- Команды старше 1 секунды игнорируются.

### 11.4. Рассинхронизация

- Сервер — источник истины.
- При расхождении клиент откатывается.
- При критическом расхождении — реконнект.
